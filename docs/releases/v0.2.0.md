Signing/notarization support and verified automatic updates. This version can be built unsigned for development; signing is an explicit manual workflow option.

- Regular CI/tag builds need no Apple credentials and publish unsigned development prereleases.
- Only manually dispatched runs with `sign_and_notarize=true` sign Mac binaries, require Apple notarization, and staple both Mac disk images. Successful signed runs can promote an unsigned development release; published signed releases cannot be overwritten.
- `agx update check` and `agx update install` support verified Mac updates using GitHub digests, pinned Apple Team ID, application identity, and notarization checks. Unsigned development artifacts are rejected.
- `agx update auto enable` opts into daily launchd updates; stable signed releases are the default. `agx update rollback` restores the exact retained previous executable.

The first signed version requires manual installation. v0.1.0 has no updater. Source/unsigned builds require an independently verified Apple Team ID to bootstrap trusted installation. Only the signed DMG can carry a stapled delivery ticket; Apple's Command Line Tools are required by the updater. No sudo is used.

Search/MCP do not perform update checks. Linux supports checks but still uses manual package/source installation. Apple signing credentials are not configured yet, so the development build does not establish successful Apple signing or end-to-end signed installation. See docs/signing-and-updates.md.
